Session Runtime Audit

Evidence captured 2026-08-22 from the live SpexCode checkout. Scope: session packages, CLI/runtime composition, watch policy, process health, and polling/lock costs.

Executive Result

P1 fixed in this audit: the canonical cutover transition path enqueued state changes to every topology recipient. That bypassed the existing policy that parent-only supervision suppresses routine active/working, while manual watch opts into it. The fix keeps the package neutral and lets the CLI pass a validated recipient set.

Not fixed here: process/app-server accumulation, synchronous SQLite busy retry, and dashboard liveness poll cadence. These are real operational costs, but changing them needs separate fail/pass evidence and can affect launch/recovery semantics.

Policy conclusion: parent and manual are additive sources, not overriding modes. For one watcher/target pair the union is one delivery: non-active transitions go to either source; routine active goes only when the manual source is present.

Immediate Change

Production transition accepts an optional validated recipient set. The CLI derives it from active watch:parent/watch:manual edges, deduplicates watcher ids, suppresses parent-only active transitions, and sends all actionable transitions. The HTTP runtime state route uses the same resolver. Existing callers that omit the option retain neutral topology broadcast semantics.

Regression coverage: session-application 12/12, CLI typecheck PASS, CLI build PASS, Dashboard tests 258/258, spec lint 0 errors (warnings are existing/drift warnings).
