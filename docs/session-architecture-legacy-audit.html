Session 架构与 Legacy 审计

结论：SQLite canonical application 已经是生命周期事实源，但旧的 session-core 文件协议仍被生产 CLI 调用。当前不是“legacy 已清零”，而是迁移已跨过状态切换，却还没有跨过通信与读取链路的删除门。

一页结论

仍有生产 legacy。 全仓库 gate 统计到 107 个生产源码引用；spex session ls --json 运行时产生 55 次 session.json 路径读取。旧读取多数是身份/运行时 envelope，但旧 queue、watch、timeline、cursor fallback 仍是真实代码路径。当前分支已切断 canonical lifecycle-only envelope rewrites，并将 canonical watch/timeline/cursor 读写收回 application；一次性迁移现在会先导入旧 timeline/pending，再删除旧通信文件，删除门仍未通过。
生命周期事实已收口。 当前 137 个 envelope 中 status、proposal、note 均为 0 个；sessions.sqlite 与 JSON migration marker 存在。hook 权限旁路已修复，canonical writer 负责治理边界。

已修复的直接越权

旧 idle/session-fail shell 曾自行 grep session.json 决定治理范围，造成 hook 层拥有第二套 authority。现在 hook 只传递 identity，canonical writer 统一检查 governed 与 active-only CAS。

迁移删除门的新证据

session-application 的 JSON cutover 现在把旧 timeline 的 status/sent 事件和 pending debt 导入 SQLite，再备份并删除 watchers.json、pending.json、timeline.ndjson、编号 timeline 段与 cursors.json；每个 envelope 只保留 runtime/worktree 元数据。迁移测试覆盖清理后的事件历史、pending 读取和 marker 重放，4/4 pass，包测试 13/13 pass。

这还不是全仓库删除完成。 未通过 dist/tarball/materialized executable/runtime trace 五项 gate 前，不删除 session-core 包，也不把迁移兼容层伪装成终态。

PreToolUse 计数核验

仓库注册数不是 6。 当前项目设置各只有一个 dispatcher 注册；live project manifest 只有两个 PreToolUse handler：mark-active 与 spec-first。它们由同一个 dispatcher 按顺序执行。
层实测结论
项目 settings每个 settings.json 1 条 PreToolUse dispatcher没有 6 条重复注册
编译后的 manifest2 个 handler：mark-active、spec-first一次工具调用最多经过这两个项目 handler
宿主显示用户看到 “Running 6 PreToolUse hooks”当前仓库证据无法解释这个展示数；应继续查宿主聚合/旧缓存，不在 hook 内增加 SQL 或状态逻辑

大重构路线

  1. 事件读取边界：让 session-application 提供稳定的 timeline/event projection，CLI 不再直接 import session-core timeline。
  2. cursor 边界：把 follow cursor 放入 SQLite application component；删除 cursors.json 读写。
  3. queue/watch 收口：让 queue debt 和 watcher source 只通过 application API 读写；删除 pending.json、watchers.json fallback。
  4. 外部 adopter 确认：若没有独立 adopter，收回 topology/runtime/events 为 application 内部模块；若有，明确公共契约并统一版本。
  5. M8 deletion gate：clean dist、npm tarball、materialized executable、runtime trace 五项均为 measured zero 后，删除 @spexcode/session-core。
禁止的终态：dual-read、dual-write、永久 translation adapter、按当前 session 特判的 fallback。

当前限制

删除门复测：生产源码 gate 已测量，runtime trace 对旧通信文件是 0 次；但一次性迁移读取器和旧 @spexcode/session-core 包仍有源码/构建引用。dist、tarball、materialized 三层本轮没有明确根目录，因此是 NOT-MEASURED，不能把 source/runtime 结果当成删除完成。当前主线还有一个与本次迁移无关的 Tooltip anchor-drift 和两个历史 Codex probe fixture 的类型漂移（本分支已修 fixture），未擅自改产品契约。
