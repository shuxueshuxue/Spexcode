Session 架构与 Legacy 审计

结论：SQLite canonical application 已经是生命周期、通信、watch 和 cursor 的唯一生产事实源。运行时只写命名的 runtime.json envelope；旧 session.json 只作为一次性迁移输入或历史夹具，不能再被当成第二套生命周期。

已修复的直接越权

旧 idle/session-fail shell 曾自行 grep session.json 决定治理范围，造成 hook 层拥有第二套 authority。现在 hook 只传递 identity，canonical writer 统一检查 governed 与 active-only CAS；worktree Codex anchor 只保留空 {hooks:{}}。嵌套 worktree 的纯 SpexCode Claude settings 也只保留一次：主 checkout 是唯一 dispatcher owner，旧副本由 materialize 精确迁移，用户自有配置不碰。

本轮聚焦回归：hook dispatch 27/27，sessions 51/51，launcher 8/8；hook 行为测试现在读取 canonical SQLite 状态，并明确断言 runtime envelope 不会被生命周期 hook 改写。仓库里仍有迁移、历史 eval 和旧 fixture 使用 session.json，它们被列为非生产输入，不能被误报成 live reader。

迁移删除门的新证据

session-application 的 JSON cutover 现在把旧 timeline 的 status/sent 事件和 pending debt 导入 SQLite，再备份并删除 watchers.json、pending.json、timeline.ndjson、编号 timeline 段与 cursors.json；每个 envelope 只保留 runtime/worktree 元数据。生产写路径与 hook dispatch 已通过聚焦回归；剩余旧名称集中在迁移输入、spec/eval 夹具和历史文档，下一轮可按删除门逐类消化。

旧包删除门已通过。 根 build、发布清单、CI、launcher source closure 和 package-lock 均不再引用 session-core；剩余 session.json 仅属于运行时 envelope 迁移，不能再被当成 lifecycle authority。

PreToolUse 计数核验

仓库注册数不是 6。 当前项目 settings 各只有一个 dispatcher 注册；live project manifest 只有两个 PreToolUse handler：mark-active 与 spec-first。它们由同一个 dispatcher 按顺序执行。Linked worktree 的 Codex anchor 已改为空 hooks，根 checkout 是唯一可执行 owner。

大重构路线

  1. 事件读取边界：session-application 提供稳定的 event projection，CLI 不再直接 import 旧通信包。
  2. cursor 边界：follow cursor 已在 application SQLite component；正常运行不读写 cursors.json。
  3. queue/watch 收口：queue debt 和 watcher source 只通过 application API 读写；pending.json、watchers.json 只存在于一次性迁移器。
  4. adopter 边界：protocol/topology/runtime/events 是可复用的中性包，Spex policy 由 application/CLI 明确组合；不以兼容包伪造公共契约。
  5. Envelope migration：已完成生产写路径切换到 runtime.json；保留一次性旧输入迁移器和删除门，禁止重新引入 dual-read/dual-write。
禁止的终态：dual-read、dual-write、永久 translation adapter、按当前 session 特判的 fallback。

当前限制

当前报告的删除门结果：旧包 source/build/lockfile/CI/materialize 生产引用为 0；生产 runtime 写路径不再创建 session.json。仓库扫描仍能找到历史 fixtures、迁移输入和文档旧名称，这些是待清理证据，不是当前运行时路径；删除前必须逐个确认不属于外部 adopter 的输入契约。

生态边界仍需单独迁移。 当前 SpexCode checkout 已没有 session-core 生产 import，但历史 ZSwarm adopter 证据曾在另一个 checkout 声明该包。它不能被“本仓库扫描为 0”掩盖：外部 adopter 必须迁到 protocol/topology/runtime stack 后，生态删除门才算完成；本报告不把外部迁移伪装成已完成。
