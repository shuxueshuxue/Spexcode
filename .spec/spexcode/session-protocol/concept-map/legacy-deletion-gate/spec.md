# session legacy deletion gate

Legacy deletion is accepted only by an executable, fail-loud gate. Each inventoried legacy facility names its
real path, current source location, hostile fixture operation, public product proof and independent deletion
measurements: production static references; separately measured dist, package-tarball and materialized
copies; and runtime file accesses. Test-only imports remain admissible attack evidence and are classified separately
from production consumers.

All sabotage runs in a disposable store, project and temporary-directory copy whose resolved paths are proven to
stay below `mktemp -d`. The gate never mutates or deletes a live session store, session record, worktree, branch or
native runtime. Product proof uses CLI, HTTP/dashboard, installed package, real hook or real harness surfaces; an
internal helper cannot close a row.

Runtime file access is measured at the kernel boundary by launching the product surface beneath `strace -f`. The
trace includes descendant Node processes, compiled output and shell hooks, and counts failed fallback probes as
legacy access. A trace that cannot first observe known legacy opens is invalid evidence. Generated deletion includes
clean `dist`, unpacked package tarballs and already-materialized executable project copies; source-only zero is not
closure. Each surface has an explicit prerequisite; missing clean-build, `npm pack`, rematerialization or successful
trace evidence is `NOT-MEASURED` and blocks the gate rather than becoming zero.

The one-way importer and its equality proof exist before the normal-runtime M6 cut. M6 may remove normal readers
only after that proof, M7 invokes the already-isolated importer with old writers stopped, and M8 deletes the importer
codecs and requires all five independently reported counts and prerequisites to reach measured zero. There is no
dual-read, dual-write, runtime fallback, old environment alias or permanent translation adapter.

SQLite transactions replace only fences around database facts. Git/worktree creation, harness launch/process
identity, resource manifests and quarantine moves retain distinct named external-effect fences until their own
owners replace them. Communication correctness loses its filesystem observer dependency, while adopter database
revision reconciliation and legitimate Git/project watchers continue to serve dashboard freshness.

Artifacts and files/web evidence, harness-discovered materialized contracts and hooks, native launch/PID/socket/
unload proof, and Spex lifecycle/worktree/branch/proposal facts are deletion-denied unless their owning adopter
independently replaces them. They are outside the communication legacy inventory and must not be removed merely
because the queue migrates.
