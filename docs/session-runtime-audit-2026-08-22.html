Session Runtime Audit

Evidence captured 2026-08-22 and updated 2026-08-23 from the live SpexCode checkout. Scope: session packages, CLI/runtime composition, watch policy, process health, and polling/lock costs.

Executive Result

P1 fixed in this audit: the canonical cutover transition path enqueued state changes to every topology recipient. That bypassed the existing policy that parent-only supervision suppresses routine active/working, while manual watch opts into it. The fix keeps the package neutral and lets the CLI pass a validated recipient set.

Still open: the old draining app-server generation is retained by exact session bindings until those clients settle; its ownership probe currently times out, so the sweep correctly fails closed. Synchronous SQLite busy retry and dashboard liveness poll cadence also remain follow-ups. No hard kill is safe while those bindings exist.

Policy conclusion: parent and manual are additive sources, not overriding modes. For one watcher/target pair the union is one delivery: non-active transitions go to either source; routine active goes only when the manual source is present.

Polling, Waiting, and Fixed Budgets

No production poll loop was found in packages/session-*. The package layer is event/transaction driven. The waits that do exist are bounded contention mechanisms, not status refreshers:

MechanismCurrent implementationAssessment
Record lock10 ms retry cadence, 30 s deadline; synchronous callers use Atomics.wait, async callers use an abortable timer.Correctly bounded, but synchronous contention blocks its Node event loop. Measure before changing.
Delivery lock25 ms retry cadence, 5 s acquisition budget; refusal keeps the head message queued.No loss and no background poll. A later supervisor pass is the retry trigger.
SQLite busy retry20 ms synchronous sleep inside the configured busy budget (default 5 s).The clearest package-level performance risk: concurrent writers can stall one event loop. It is a known follow-up, not evidence of a status flood.
Schema limitsIDs, metadata, event bodies, and message bodies have explicit byte/count limits.These are validation boundaries, not accidental magic waits.

The repeated working messages observed in the dashboard were therefore not caused by a session-package timer. The live flood came from the cutover policy bypass and from explicit manual-watch edges; the parent-only rule now suppresses routine active transitions.

Policy Composition and Layer Boundary

The package represents a watcher/target relationship once and keeps the source set as a union: sources: ["parent", "manual"]. Adding a second source does not create a second edge or duplicate delivery. The package's neutral transitionSession API accepts an optional, validated recipient set; it does not know what “parent policy” or “manual policy” means.

ConcernOwnerResult

This is intentionally not a policy override chain: parent and manual are a set union. A parent edge cannot suppress a manual edge, and removing the parent source removes only its initial-snapshot debt. This matches the requested semantics without adding another policy registry or another status axis. The live ded4b563 repair also confirmed that the CLI's default watch command is manual by design; parent restoration must use the parent-source path owned by reparent/registration.

Runtime Ownership Finding

The Codex socket is held by the native app-server process, not by the SpexCode backend. The pre-rotation census showed one loaded listener, eight durable Codex clients, and 28–33 established server-side Unix streams. Process inspection found the client-side descriptors under native codex --remote ... resume processes; SpexCode's short JSON-RPC operations call conn.destroy() on success, timeout, error, and close. The backend's HTTP socket reaper covers abandoned HTTP keep-alive sockets and explicitly exempts active WebSocket/SSE streams.

Conclusion: the sampled connection/RSS movement is not monotonic, so ownership of a leak is unproven. Formal rotation is the safe restart mechanism: the old generation is draining, a fresh generation accepts new launches, and no active client or durable state was destroyed. The old generation cannot be reclaimed until its exact bindings disappear and two native censuses prove zero references; the current timeout therefore remains a retained-resource finding, not permission to bypass the guard. The exact safe cleanup also reaped four zero-reference generations and removed 1767 dead zero-byte socket files.

Immediate Change

Production transition accepts an optional validated recipient set. The CLI derives it from active watch:parent/watch:manual edges, deduplicates watcher ids, suppresses parent-only active transitions, and sends all actionable transitions. The HTTP runtime state route uses the same resolver. Existing callers that omit the option retain neutral topology broadcast semantics.

Regression coverage: session-application timeline 2/2 for legacy Claude delivery, canonical queue tests 40/40, CLI build PASS, Dashboard tests 271/271, spec lint 0 errors (warnings are existing/drift warnings).
