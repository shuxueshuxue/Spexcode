# What each failure log proves

Both logs are kept verbatim. Neither has been edited, regenerated, or overwritten by a later run.

## `fail-first.log` — kept, but it proves almost nothing

The first failure recorded on this lane, `ERR_MODULE_NOT_FOUND` for `engine.mjs`, produced before the
engine existed:

```
node --test test/engine.test.mjs        # from spikes/sqlite-m2/, with engine.mjs absent
```

It is retained because it is the original artefact. It is **not** the fail-first evidence for any
frozen decision: a missing module fails identically whether the eventual implementation is right or
wrong, so it discriminates nothing. It records only that the vectors were written before the engine.

## `evidence/fail-first-discriminating.log` — the real counter-example

The same vectors, unchanged, driven against a deliberately wrong implementation:

```
cd spikes/sqlite-m2
npm install --no-save better-sqlite3          # only needed for the driver-parity run
node stubs/build.mjs
M2_ENGINE=../stubs/producer-minted-message-id.mjs node --test test/engine.test.mjs
```

Every failure in that log is one of our own assertions naming the violated claim. The stub differs
from `engine.mjs` in exactly three places, all generated by `stubs/build.mjs`.

`evidence/counterexamples.txt` is the same treatment for all seven stubs, produced by
`node stubs/run.mjs`. That runner refuses to count a stub that fails to load: a module error is
reported as `HARNESS FAILURE, not a counter-example` and the run exits non-zero, so "did not
measure" can never be mistaken for "measured and fine".
